# Phase 10 Product UX Flow

Phase 10 composes the accepted Phase 1–9 feature modules into one product workspace. It adds presentation and interaction hierarchy only; it is not a transaction, policy, risk, AI, monitoring, or simulation authority.

## Product hierarchy

The application shell contains a compact header and environment disclosure, the Adaptara hero and authority statement, the functional portfolio workspace, a system/trust explanation, and a disclosure footer. The workspace groups information as Portfolio, Intelligence, Strategy, and Guardrails.

## Wallet and vault experiences

`Your Wallet` is the default source and provides read-only Portfolio Intelligence, Adaptara Sentinel, Risk Intelligence, and explicitly requested MARA interpretation. It never implies that Adaptara manages the connected wallet.

`Adaptara Vault` is a separate presentation source. An available vault adds Adaptation Simulation, Yield Intelligence, and its Financial Constitution. When no vault is configured, created, or readable, the UI states that truthfully. Yield Intelligence remains discoverable with canonical sandbox terms, but cannot invent a principal or projection. No Phase 10 vault-creation action exists.

Source switching changes presentation only. It does not scan Sentinel, analyze with MARA, generate an adaptation, run yield, write policy, or send a transaction. Existing context fingerprints continue to prevent results from appearing for a different source, account, chain, snapshot, or policy context.

## Primary journey and explicit actions

The intended journey is: connect a wallet; confirm X Layer Testnet; inspect a wallet or vault portfolio; explicitly run Sentinel; review deterministic Risk Intelligence; explicitly analyze with MARA; explicitly generate an eligible Adaptation Simulation; review the vault Financial Constitution; and explicitly run an eligible compounding simulation.

The preserved explicit controls are `Run Sentinel Scan`, `Analyze with MARA`, `Generate Adaptation Simulation`, `Run Compounding Simulation`, and the previously reviewed `Save Constitution Onchain`. Adaptation and yield are simulation-only. MARA is advisory only. There is no execution, swap, approval, deposit, withdrawal, claim, rebalance, or scheduling control.

## State design

Disconnected and wrong-network states occupy the workspace without fabricated data. Wallet and vault reads have contained loading states. Empty supported balances, undeployed sandbox tokens, unavailable valuation/risk/MARA, and vault configuration/discovery/read failures retain distinct truthful copy. Errors are never converted to zero balances or fallback results.

## Responsive and accessible behavior

The shell uses available desktop width and collapses to a single column on mobile. Source tabs remain full-width tap targets, vault section navigation scrolls when necessary, readiness tiles stack, and cards cannot force page overflow. Controls use semantic buttons, tabs expose `aria-selected`, navigation uses anchors, asynchronous state uses status/alert semantics, focus remains visible, and motion is reduced under `prefers-reduced-motion`.

## Disclosures

The shell identifies X Layer Testnet, demo/non-live inputs, and sandbox RWA limitations. Sandbox assets have no redemption rights. Risk is a current measurement, not a return prediction. Current Adaptation Simulation and Yield Intelligence outputs have no execution authority and do not represent live performance.
